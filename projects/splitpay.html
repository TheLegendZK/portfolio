SplitPay

Flutter, Dart, Riverpod, Firebase

View source on GitHub Request a demo

App Screenshots

Problem

Keeping track of shared expenses across a group can make it difficult to see who owes what and how to settle up. SplitPay centralizes group expenses and calculates simplified balances.

What I Did

  • Architected a Feature-First Clean Architecture (auth, groups, group_detail, settlements) using Riverpod reactive streams and controllers to manage real-time group expenses and invitations.
  • Engineered a Greedy Debt-Simplification Algorithm (SettlementCalculator) that computes net balances and minimizes total peer-to-peer transactions, supporting weighted headcount shares (e.g., 1x solo vs. 2x couple splits).
  • Implemented atomic Firestore WriteBatch operations for group creation, invitation lifecycle management, and cascading deletes, backed by custom Firestore Security Rules enforcing authenticated Role-Based Access Control.
  • Built a custom reusable widget library (SplitPayCard, AsyncElevatedButton, SplitPayModalSheet) featuring creator-verified swipe-to-delete (Dismissible) with instant SnackBar undo restoration and unit tests verifying settlement math.

Result

The greedy debt-simplification algorithm consolidates a complex group tab into a minimal set of peer-to-peer settlements, reducing unnecessary repayments while supporting weighted shares. Custom Firestore security rules restrict expense edits to authorized group members.
